## 2026-11-04 · feature/waypoint-graph-pathing

오늘 한 작업
* 요지 그래프(구현 2번): 요지 = 시나리오 데이터(이름·종류·중심·반경, 종류 = 고지/숲 가장자리/길목/대기 지점/사격 진지). 불러올 때 계산하는 것 — 요지별 시야 영역(요지 안 다섯 지점에서 보이는 칸의 합집합), 구간(이웃 요지 쌍의 격자 경로, 길이·엄폐 비율·요지별 가시 비율)
* 구간은 이웃끼리만: 모든 쌍의 경로를 구한 뒤 ① 다른 요지 영역을 지나는 쌍 ② 다른 요지를 거쳐도 거의 같은 거리(1.2배 이하)인 쌍을 뺌. 테스트 지도 요지 11개 → 구간 17개
* 격자 경로 탐색: 10m 칸 8방향 A* → 경로 펴기 → 곡선화(Chaikin 2회) → 웨이포인트 여러 개. 이동 방식별 비용(RulesConfig의 Fast/Normal/StealthPathCost): 신속 = 거리·경사 위주, 일반 = 균형, 은밀 = 노출·개활지를 크게 피함(숲 선호)
* 노출 지도(ExposureField): 칸마다 "얼마나 보이는 곳인가". 요지별 무게로 만들기(BuildExposure — 3번 의심 지점이 쓸 것), 관측자 위치로 만들기(AddObserver)
* 테스트·방어 시나리오에 요지 11개(같은 지도라 공용): 남쪽 출발 지역·남서 숲·남서 숲 북쪽 가장자리·능선 서쪽·능선 중앙·도로 능선 길목·동쪽 고지·동쪽 숲 북쪽 가장자리·중앙 진지·동쪽 진지·북쪽 후방
* 디버그: G = 요지·구간 겹쳐 보기, Ctrl + 우클릭 = 경로 탐색 이동(노출 기준 = 블루 상황판의 접촉, 확인 1·소실 0.5). QA용 — 직접 조종 제거 때 같이 정리
* 테스트 11개 추가 (총 90개)

문제 / 결정 사항
* 그래프는 처음 쓸 때 계산(테스트 지도 1.2~1.4초). 쓰지 않는 판·테스트는 비용 없음. 판정·난수를 건드리지 않아서 기존 판 결과는 그대로(회귀 해시 두 개 모두 변경 전과 같음)
* 직접 이동 명령(OrderMove)은 그대로 직선 — 경로 탐색은 지휘관(4번)과 디버그 Ctrl + 우클릭만 씀
* 노출은 경로를 짜는 쪽이 아는 것으로만 만듦(반칙 금지). 실제 적 위치는 안 씀
* 경로 펴기 허용 폭을 비용 비율(%)이 아니라 거리 기준으로: 노출이 큰 구간(능선 넘어 진지 앞)이 끼면 허용 폭이 커져서 은밀 경로의 숲 우회가 통째로 지워졌음
* 곡선화도 비용 확인: 모서리를 깎은 직선이 원래 모서리보다 비싸면(노출 칸을 파고들면) 그 모서리는 안 깎음 — 은밀 경로가 보이는 땅 모서리를 밟던 문제
* 위협이 없으면 신속·일반 경로는 거의 직선(이 지도는 경사가 완만함). 곡선·우회는 노출이 있을 때 나옴 — 지휘관이 의심 지점(3번)을 가지면 평소에도 나옴
* 일반 이동 비용에서 숲은 느려서(속도 0.6) 돌아가는 쪽이 싸다. 은밀만 숲을 탐. 구간 성질은 일반 이동 경로 기준으로 계산
* 시야 영역 계산은 칸 수 × 시야선 길이라 10km 섬 지도에서는 칸 크기·관측 범위 조정이 필요(지금 1km 지도 기준)

다음 작업
* 3번: 상황판 새 항목(의심 지점, 실제 부대에 안 묶임) + 브리핑 생성(정보 신뢰도만큼 오차, 시드 결정론) + 관측 갱신. 의심 지점 확률 → BuildExposure → 경로 비용

QA 때 볼 것
* G로 요지 위치·반경이 지형과 맞는지(특히 "남서 숲 북쪽 가장자리", "동쪽 숲 북쪽 가장자리"가 실제 숲 가장자리에 있는지), 구간이 말이 되는지
* Ctrl + 우클릭: 적 접촉이 있을 때 은밀 경로가 숲·능선 뒤로 도는지, 웨이포인트가 촘촘해 경로 선이 어지럽지 않은지
* G를 처음 켤 때 1초 남짓 멈춤(그래프 계산)
* 요지 반경(30~60m)과 "다른 요지를 거치면 1.2배 이하" 기준은 임시 값

공개용 메모
* "지휘관은 지도를 점과 선으로 생각하고, 병사는 땅을 걷는다" — 요지 그래프 위에 은밀 경로가 숲을 타고 도는 그림
* 오늘 그림: 요지 그래프와 이동 방식별 경로(은밀만 숲 가장자리를 탐)

## 2026-11-04 · feature/suppression-cover

오늘 한 작업
* 제압 = "못 움직임"이 아니라 "앞으로 못 감"으로 바꿈. 제압된 소대는 가장 가까운 아는 위협 쪽(진행 방향 ±60°)으로는 5% 속도, 옆·뒤로는 25% 속도로 움직임(이전: 속도 0)
* 엄폐 후 응사 = 그 자리 정지가 아니라 가까운 엄폐(반경 50m)로 간 뒤 정지. 엄폐 = 숲 칸, 또는 아는 위협 전부에서 시야선이 가리는 칸(역사면·둑 뒤). 엄폐가 없으면 이전처럼 그 자리 정지
* 제압된 채 명령 없이 엄폐 밖에 있으면 스스로 엄폐로 기어감. 경계 중이었으면 엄폐에 닿은 뒤 경계 방향을 되살림. 대기 지점에서 기다리는 소대는 움직이지 않음
* 보고 문구: "제압됨 — 전진 불가", "접촉 — ○○ 엄폐로 이동, 응사", "제압 — ○○ 엄폐로 이동", "○○ 엄폐"
* 새 수치는 RulesConfig(PinnedForwardSpeedFactor 0.05 / PinnedOtherSpeedFactor 0.25 / PinnedForwardArcDegrees 120 / CoverSearchRadius 50 / CoverSearchRetrySeconds 10). 엄폐 찾기·제압 중 속도는 새 파일 Simulation.Cover.cs
* 테스트 7개 추가 (총 79개)

문제 / 결정 사항
* 관찰형에서는 제압당한 소대가 얼어붙은 점이 아니라 엄폐로 기어가며 버티는 부대로 보여야 함(설계 3회차). 디버그에서도 거슬렸던 부분
* 위협 방향은 소대가 아는 적만 씀(자기가 추적 중인 적 + 통신되면 본부의 확인된 접촉, 붕괴 후퇴와 같은 규칙) — 반칙 없음. 어디서 쏘는지 모르면 전부 25%, 엄폐는 숲 칸만
* 제압 중에는 기존의 "제압만큼 속도 감소"를 곱하지 않고 5%/25%로 대신함(둘을 곱하면 25%가 실제로는 약 11%가 됨)
* 엄폐 이동은 명령이 아니라 반응이라 대기·신호·통지를 건드리지 않고, ○소대 도착 통지도 내지 않음. 새 명령·붕괴 후퇴가 오면 취소
* 대기 중 소대는 제압돼도 안 움직임 — 대기 지점의 의미가 깨지고, 지휘관이 대기 지점을 엄폐된 요지로 고를 예정이라서
* 엄폐를 못 찾으면 10초마다 다시 찾음(매 틱 훑지 않게). 이미 엄폐 안이어도 위협이 움직일 수 있어서 같은 간격으로 다시 봄
* 구현 순서 확정(11-04): 설계서 "구현 순서" 초안에서 두 가지를 바꿈 — ① 4번(공격 지휘관 코어)·5번(방어 일반화) 끝에 콘솔 분포 검증을 넣고, 4번에 판단 요인 점수 로그 + 디버그의 소대별 목적·경로 표시를 같이 넣음(지휘관 품질이 가장 큰 위험인데 끝에서야 확인되는 걸 막으려고) ② 수송 웨이브를 상급부대 정보 층보다 먼저(웨이브는 지휘관의 재계획 지점이라 지휘관 코드 직후가 덜 헤맴)
* 회귀 기준을 새 측정 도구로 다시 잼(이전 도구가 남아 있지 않아 이전 해시 형식을 재현 못 함). 사건 로그 형식 = 판마다 "경과초|진영|문장\n"을 이어 붙인 UTF-8의 MD5
  * 지휘관 없는 판(테스트 시나리오 시드 1~40, 1800틱): A8F6FB02812E28CB523F3803128CADC5 — 변경 전후 동일(이 판에선 제압이 안 생김)
  * 공격 판(10-28 스크립트 그대로, 테스트·방어 시나리오 각 40판): 변경 전 0B514DB6A240F725E8ED11E394201BD5 → 변경 후 0BDFC1BFAD49227A19DBF2A19B21BAA5
* 밸런스: 공격 판 스크립트 블루 승리 테스트 1→0 / 40, 방어 0→0 / 40. 엄호+우회 스크립트(1소대 남서 숲에서 엄호 경계, 2소대 동쪽으로 돌아 돌파)는 변경 전후 모두 0/40(테스트 시나리오 블루 사상 1154→1156, 레드 사상 26→36). 스크립트 공격은 변경과 상관없이 거의 다 짐 — 의미 있는 밸런스 기준선은 공격 지휘관(4번)이 생긴 뒤 다시 잡음

다음 작업
* 2번: 요지 그래프 + 구간 성질 계산 + 격자 경로 탐색(A* → 펴기 → 곡선화). 테스트·방어 시나리오에 요지 데이터. 직접 명령(OrderMove)은 그대로 직선

QA 때 볼 것
* 제압된 소대가 5%로 기어 나가는 게 "멈춘 것"과 구분되는지(1800초 동안 수십 m)
* 엄폐 이동 속도(일반 이동, 제압 중이면 25%) — 50m에 3분 남짓. 너무 느리면 엄폐 이동만 따로 값 두기

* 디버그 화면에서 엄폐 이동이 일반 이동과 똑같이 보임(이동 표시만). 개입 화면 단계에서 기호로

## 2026-11-03~04 · 설계: 현장지휘관 AI 1~5회차 (코드 변경 없음)

오늘 한 작업
* 설계서 "지휘 워게임 — 관찰형 전환 설계서"에 현장지휘관 AI 설계 다섯 회차를 정리: ① 구조(작전 계획 / 상황 조정 / 소대 세 층, 점수 = 이유) ② 지형·정보 입력(요지 그래프, 의심 지점, 브리핑, 상급부대 정보 층, 정보 핑) ③ 공격 작전 짜기(소대마다 목적 + 경로 + 타이밍, 개시 시각, 화면 문법, 제압·엄폐 엔진 변경) ④ 방어 작전·수송 웨이브 ⑤ 핑 반영·답장·요청·무전
* 코드 변경 없음

문제 / 결정 사항
* 점수 = 이유: 후보마다 이름 붙은 요인(예상 노출·예상 손실·소요 시간·불확실성·기습 가능성·목표 기여·상급 지시 부합)을 계산하고 성향은 요인 가중치. 고른/깎인 요인이 그대로 무전 문장과 AAR이 됨. 기존 방어 지휘관의 신중·공격 두 점수 공식을 대체
* 이름 붙은 작전안(정면 강습·망치와 모루 등)을 고르는 구조는 폐기 — 작전 이름은 사전 지식 없는 플레이어에게 아무것도 알려 주지 않음. 지휘관은 소대마다 목적 다섯(제압·진격·유인·정찰·예비) + 경로 + 타이밍을 짜고, 이름 붙은 작전은 결과로만 나타남
* 성향은 공격적·신중함·기만 선호 셋만 작동(템포·정보·기동 축으로 갈려 리플레이에서 구분됨), 교범 중시·병력 보존 우선은 잠금. 성능은 양쪽 동일, 성향은 가중치만
* 판단은 요지 그래프, 이동은 10m 격자 경로(이동 방식별 비용 → 펴기 → 곡선화). 노출 비용은 지휘관의 의심 지점 기준이라 반칙 없음
* 의심 지점: 브리핑 적 규모를 요지에 점유 확률로 배분, 관측으로 갱신. 정찰의 가치 = 불확실성 감소 → 신중함이 특별 규칙 없이 정찰을 먼저 보냄
* 진영마다 상황판 둘: 현장(지휘관이 봄) / 상급부대(플레이어 화면: 현장 중계 + 지연, 드론 등 상급 자산). 드론 정보는 정보 핑으로만 지휘관에게 내려감
* 개시 시각(H시)은 지휘관 전용 공통 능력(신호에 항상 백업). 플레이어는 설정 안 함 — 디버그에서 H시가 생소해 건너뛰게 됐던 경험이 근거
* 화면 문법: 상태는 기호로(고리 = 전투 상태, 막대 = 전투력, 배지 = 기다리는 이유·통신, 선 모양 = 정보 신선도), 글자는 의도·요청·클릭 때만
* 방어도 같은 목적·단계로. 진지 장소는 시나리오, 소대 배치는 지휘관. 양쪽 다 자기 수송 일정만 알고 상대 것은 모름
* 핑은 "상급 지시 부합" 요인으로 들어감. 답장 = 전체 최선 vs 지시를 따르는 최선 비교(수행 / 해석 수행 / 조건부 / 승인 요청 / 거부 + 대안). 대안 = 따르는 후보를 가장 많이 깎은 요인의 처방(노출 → 포격 후라면, 불확실성 → 정보가 있으면 등)

* 플레이 중 발견: 진지에 적이 남아 있는데 확보 성공이 뜸. 기획 결정은 "적 없이 60초"였는데, 구현이 "싸울 수 있는 적 없이"로 판정해서 붕괴한 적을 없는 것으로 셌음(60초 타이머는 정상). 붕괴한 적도 막도록 수정 — 진지에 적이 남아 있는 한 점령이 아니고, 붕괴한 적은 스스로 물러나므로 영원히 막지 않음

다음 작업
* 계획 명령(feature/plan-orders 제안) — 대기 지점·신호 대기·조건부 출발. 작전의 동시성(포위·망치와 모루·성동격서)을 반사신경이 아니라 계획으로 맞춤. 신호도 통신을 탐. 장비 맵(차량·헬기)일수록 필요 — 이벤트 일시정지보다 먼저
* 2단계: 의외성 예산(판당 0~1회) + 사전 징후 + 부성향(버릇), 브리핑 성향 게이지
* 또는 공격하는 적 / 난이도 손잡이(내다보기·협동·정찰)
* 사건 알림(feature/event-pause): 일시정지 = 지금 결정할 게 있는 사건(첫 접촉 = 새 접촉 번호, 점령 시작) / 경고 문구 = 알아야 하지만 당장 명령할 게 없는 사건(소대 첫 피해, 전투 가능 70%·50% 아래, 붕괴). 경고는 실제 시간 기준으로 표시(배속과 무관), 여러 개면 쌓아서 보여줌. 본부가 아는 사건만(보고 도착 시점). 통신 두절은 일부러 제외 — 아군 소대를 자주 살피는 습관이 재미, 막상 보면 끊겨 있는 상황이 연출되게

QA 때 볼 것
* 성향별 판단 분포(블루 3개 소대가 1진지로 돌파 이동하는 스크립트, 20판): 공격성 0.1 = 고수·증원만, 0.35 = 증원 18·역습 2, 0.9 = 매판 역습. 블루 승리는 성향과 상관없이 0/20(판정 수정 전에는 0.9에서 8/20이었지만, 역습한 예비대가 붕괴한 채 진지에 남아 있는데 확보 판정이 난 판이었음)
* 확보 판정 수정의 영향: 테스트 시나리오 블루 2개 소대 돌파 스크립트 40판 승리 10 → 4. 기존 밸런스 기준선(엄호+우회 40판 중 2판)도 다시 잴 것
* 후퇴는 스크립트 판에서 한 번도 안 나옴(역사면 진지가 피해를 거의 안 입음). 플레이어가 진지를 실제로 몰아붙이면 나오는지
